## Design Specificity Verdict

**LLM assessment：类别可替换（category-interchangeable）。** 把侧栏文案换成“订单/库存/供应商”，这套 shell 仍然成立。220px 深蓝侧栏、假面包屑、常驻全局搜索、白卡片铺灰底、Element 默认蓝绿、斑马纹表格——这是通用后台骨架，不是知识工具的语言。仅有的产品指纹（力导向图、聊天引用卡、思考链）仍是库默认样式；更关键的是，产品链路没有被表达：文档没有抽取结果，节点没有来源文档，OCR 没有“进入抽取”，AI 服务只能粘贴文本。唯一连回来源的引用卡，点击后只打开文档元数据弹窗。与目标 DESIGN.md 的方向冲突集中在：深色侧栏 vs 浅色索引栏、面包屑 vs 无面包屑、三主色 vs 单一信号蓝、默认投影 vs Flat-By-Default、ECharts 默认色 vs 图谱分类墨。

**Deterministic scan：** `impeccable detect --json knowledge-ui/src` 退出码 2，仅 1 条 `overused-font`（warning/slop，`App.vue:121`，全局 font-family 声明）。该规则列出的字体不含 Helvetica，且中文字形会回退到 PingFang/微软雅黑，属于低信号、理由不匹配的发现，不是 .vue 解析误报。检测器未报告对比度、可访问名称、空/错态——这些不在其模式规则内，沉默不等于不存在。

**Visual overlays：** 不可用。REA 浏览器工具没有任意 JS 注入/求值原语，未启动 `impeccable live-server`，未注入 `detect.js`，不宣称存在用户可见 overlay。回退证据为：1440×900 截图、DOM、无障碍树、console 与 network 事件。

## Overall Impression

这是一个能跑通 CRUD 的 Element Plus 后台骨架，有一个真正好的想法（证据优先的聊天）和一套认真的领域建模；但产品的核心承诺——一条链路、可溯源、本地优先——在界面上基本不可见，失败状态全部塌缩成“空表 + 英文 toast”。最大的机会不是美化，而是让知识链路成为界面本身，先从“引用 → 原文页码/分块”的闭环和真正的空图谱开始。

## What's Working

1. **聊天的“证据优先”结构**：助手气泡内的 `inline-related-docs` 把文档名、页码 tag、文件类型、相似度和 hover 箭头排成一行；右侧 `related-panel` 再给关联节点和图。这是全站唯一把“答案→来源”做成可扫读组件的地方。
2. **AI 等待体验有意识**：思考链折叠、8×18px 流式光标、生成中“停止”按钮、`init` 阶段先下发 RAG 文档再出 token——方向比多数 CRUD 后台更懂 AI 交互。
3. **领域类型体系与图谱机制**：9 类节点/9 类关系及中英映射、手动/抽取来源标记、权重→线宽、0.3 曲率、邻接强调，都是应该带走的领域资产。

## Priority Issues

### [P0] 错误、空态、离线、异步进度与删除后果共用一套“toast + 暂无数据”模型
- **Why it matters**：本地优先产品的后端/Ollama 离线是正常状态，不是异常；用户无法判断“没有数据”还是“服务挂了”，也无法恢复。删除来源文档可能静默破坏图谱与引用，却没有影响范围或撤销。
- **Fix**：为每个数据区域定义 loading / empty / error / offline 四态；错误态给中文原因、重试与“检查本地服务”；用 `/api/health` 做常驻服务健康条；解析/OCR 变成可见队列（排队/处理/完成/失败 + 完成通知 + 行内重试）；删除前给出分块/实体/关系/引用影响计数，提供软删除、回收站或 undo toast。
- **Suggested command**：$harden（文案由 $clarify 收口）

### [P1] 导航按能力切分，知识链路不可见
- **Why it matters**：7 个一级入口是能力清单（图谱、对话、节点、关系、文档、OCR、AI 服务）；文档/OCR 排在第 5/6 位；没有总览或处理队列。用户必须自己在脑中拼出“上传→解析→抽取→图谱→问答”，第一次使用不知道从哪开始。
- **Fix**：按链路重组 IA：资料入库（文档/OCR）→ 处理队列 → 图谱/实体检查器 → 问答；合并节点与关系为“图谱 + 检查器”；AI 服务降为设置/开发者抽屉；页面标题 18px + 每屏一个主动作；去掉假面包屑与常驻全局搜索，或改成有作用域的命令面板。
- **Suggested command**：$shape

### [P1] 首屏与空态没有“第一课”
- **Why it matters**：首页是一整张空白图谱卡；聊天同时出现两个空态和两个“新对话”按钮；AI 服务三块空 textarea。后端一停，所有页面都像坏掉；即使后端正常，空库用户也没有可探索的起点。
- **Fix**：做“空地图”而不是“空卡片”：导入文档 + 加载示例图谱 + 三步流程说明；每个列表空态一句话 + 一个动作；聊天只保留一个空态和一个 CTA；提供可一键载入的演示数据；在空态里说明数据留在本机。
- **Suggested command**：$onboard

### [P1] “可溯源”的承诺在交互上断链
- **Why it matters**：引用卡显示页码与相似度，点击只打开文档元数据弹窗，没有 PDF 页码/分块高亮；`goToNode` 同时传 `nodeId` 和 `keyword`，但 GraphView 只监听 `keyword`，同名节点会落到错误对象；“查看子图”直接替换当前图，返回全图只能靠“刷新”猜；筛选与选中状态不进 URL。
- **Fix**：引用点击打开文档阅读器并定位页码/分块、高亮原文；节点深链直接聚焦并打开检查器；子图提供面包屑/返回并保留父图状态；筛选、选中节点、当前文档写入 URL；节点表“查看图谱”按 ID 聚焦。
- **Suggested command**：$shape

### [P2] 可访问性与对比度系统性不达标
- **Why it matters**：蓝链接 2.78:1、白字绿钮 2.24:1、侧栏激活 3.75:1、12px 灰元数据 2.85:1、表头 3.08:1；页面无 heading；会话项、引用卡、关联节点是 `div @click`；会话“更多”菜单 hover 才显示；图标按钮无 `aria-label`；图谱 canvas 无文本替代；焦点环 2.78:1。
- **Fix**：用舆图蓝（5.19:1）替换可读链接色；正文/元数据改 `#4E5969`/`#1D2129`；可点击 `div` 改 `button`/`a` 并加 `role`/`tabindex`；hover 菜单同时支持 `:focus-within`；图标按钮加 `aria-label`；每页加 `h1`；图谱提供节点/边数据表或可读列表替代；加 skip-to-content。
- **Suggested command**：$audit

## Persona Red Flags

**Alex（Power User）**：500 节点时 `label.show: true` 全部显示，必然糊成一团；没有类型筛选、聚类、路径查询 UI，尽管 API 已有 `getPathGraph/findPath/getNeighbors`。表格“查看图谱”只做关键词搜索；聊天点节点传了 `nodeId` 却被忽略，同名节点会错。`查看子图` 是单向陷阱。列表固定 10 条/页，无批量、排序、列配置、保存视图、导出；筛选不进 URL。聊天回答不能复制/重新生成/编辑引用；没有会话搜索或队列状态。

**Sam（Accessibility）**：会话项与引用行是 `div @click`，键盘无法聚焦；`session-more` 只有 hover 才 `opacity:1`，键盘用户永远看不到重命名/删除。附件回形针、更多菜单是纯图标按钮，无 `aria-label`；多个 combobox 无可访问名称。首页图谱是 canvas + 图例，屏幕阅读器没有节点/关系文本替代；无 heading、无 skip link。蓝链接、绿按钮、12px 灰元数据全部低于 4.5:1。错误 toast 有 `role=alert`（正确），但内容是英文且 3 秒消失。

**Jordan（First-Timer）**：没有页面标题、引导或示例；“AI 服务”与“AI 对话”同图标，让他不知道问答去哪。首页空白图谱 + 404 像产品没装好；聊天两个“新对话”CTA 造成犹豫。“关联知识库”没有范围说明；“语义搜索”结果只有 ID/类型/相似度；抽取只能粘贴文本，没有“从文档抽取”的入口；上传格式只藏在 `accept` 属性里。

## Minor Observations

- `AI对话` 与 `AI服务` 共用 `ChatDotRound` 图标；logo 是通用 `Connection` 图标，favicon 仍是 Vite 默认。
- 0 行时仍显示完整分页器（共 0 条、10 条/页、页码、跳转）。
- ID 列固定 180px；文档页在 1440 宽下“创建时间”被固定操作列截成“创建时”，表头与操作列重叠。
- 节点/关系页 list + types 同时失败时叠两条相同 toast，第二条盖住工具条按钮；5 秒后完全消失，页面回到“暂无数据”。
- 面包屑“首页”实际指向图谱页，且当前页在侧栏与面包屑重复。
- 关系弹窗两个节点选择器外观相同、共享 `nodeOptions`、没有 source→target 方向；选项显示英文类型 `(Person)`，表格却显示“人物”。
- 节点“扩展属性”是自由 JSON textarea，无校验；“关系权重”0–1 滑杆在表格与图谱中没有解释。
- 思考链标题的 Loading 图标在回答完成后仍持续旋转。
- 回答没有复制、重新生成、引用展开，也没有“本次引用 N 篇”的汇总。
- `markdown-it` 配置 `html: true`，聊天与文档摘要使用 `v-html`，缺少消毒。
- PRODUCT 提到的“模型配置、向量生成测试”在 AI 服务页不存在；OCR 结果没有“进入知识抽取”动作。
- 顶栏全局搜索只响应 Enter，且会离开当前页并丢失未保存草稿（AI 文本、节点表单）。
- dev server 观察限制：后端 404，无法评估真实数据下的图谱可读性、流式聊天、引用卡、详情弹窗与上传进度。

## Questions to Consider

1. 对一个“本地优先、后端可以离线”的产品，后端不可用到底应该显示为错误，还是进入一种只读/离线地图模式？如果离线是常态，为什么界面把它当异常？
2. 如果“答案可溯源”是定位差异点，为什么引用卡只能打开元数据弹窗，而不能落到 PDF 页码/分块并高亮原文？
3. 图谱是首页，但空图谱是整站最空的屏。新前端是否应该让“地图”在没有数据时也能表达结构——处理队列、最近文档、示例图？
4. 节点和关系真的需要两个 CRUD 页面吗？在 Atlas 里它们更像同一张图的检查器与筛选器，拆成两张表是不是把数据库结构直接暴露成了导航？
